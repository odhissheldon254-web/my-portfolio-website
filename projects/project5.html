Project 05 — WiFi & Networking

ESP32 WiFi Sensor Logger

This project moves from the Pico W's local web server (Project 3) to the other side of the same pattern: an ESP32 that reads a sensor and pushes the data out over WiFi as an HTTP client, the way a real IoT device reports back to a server.

Project Goal

Read temperature and humidity from a DHT22, join a WiFi network, and POST each reading as JSON to a real HTTP endpoint on the internet — not a mock, an actual outbound request from the simulated board.

Components

  • ESP32 DevKit V1
  • DHT22 temperature and humidity sensor
  • Arduino core libraries: WiFi.h, HTTPClient.h
  • DHT sensor library + Adafruit Unified Sensor (Arduino Library Manager)

How It Works

The ESP32 joins Wokwi's simulated Wokwi-GUEST access point, which proxies real internet access from inside the simulator, then makes an actual outbound HTTP POST to httpbin.org on every reading.

// ESP32 WiFi Sensor Logger — DHT22 over HTTP POST #include <WiFi.h> #include <HTTPClient.h> #include <DHT.h> const char* ssid = "Wokwi-GUEST"; const char* serverUrl = "http://httpbin.org/post"; DHT dht(15, DHT22); void setup() { Serial.begin(115200); dht.begin(); WiFi.begin(ssid, ""); while (WiFi.status() != WL_CONNECTED) delay(500); } void loop() { float t = dht.readTemperature(); float h = dht.readHumidity(); HTTPClient http; http.begin(serverUrl); http.addHeader("Content-Type", "application/json"); int code = http.POST("{\"temperature\":" + String(t,1) + ",\"humidity\":" + String(h,1) + "}"); Serial.println(code); http.end(); delay(10000); }

What I Learned

Getting an ESP32 sketch onto a free-tier simulator taught me as much about build infrastructure as about firmware: HTTPS pulls in the mbedtls/TLS stack, which is by far the heaviest thing to compile on ESP32, so this uses plain HTTP to keep the build lighter. It's also a reminder that "my code is correct" and "the platform I'm testing on is available" are two different things worth debugging separately.
